# 新增渠道方法论

## 探测（只读，先别写代码）

1. 浏览器手动完成一次检索；
2. DevTools → Network：找数据来源（**JSON 接口优先**；纯 DOM 则记录结果容器选择器）；
3. 验证认证方式：清 cookie 还能用 = IP 认证；
4. 记录分页方式与每页条数。

## 判断渠道类型

| 类型 | 特征 | 实现方式 |
|---|---|---|
| HTTP/JSON | 返回 JSON，无需浏览器 | `fetch` + 解析（见 `sources/openalex.js`） |
| 页面渲染 | 结果在 HTML/DOM | 受控 Chrome + 注入抽取脚本 |
| 需交互 | 点"下一页"/切类型/点开详情 | CDP 点击 + 条件等待 |

## 现成骨架

仓库自带两个模板，复制改名即可：

- `sources/_template-http.js` — JSON/HTTP 渠道（约 60 行）
- `sources/_template-browser.js` — 浏览器渠道（约 100 行）

## 三段式实现

1. **定位**：`Page.navigate` + 等 URL 变化 + `waitFor(结果容器)` + 等数量稳定；
   **不要等 `load` 事件**（有的站 load 需要 60s）。
2. **抽取**：注入一段 JS，返回 `JSON.stringify({items, ...})`，字段统一。
3. **取链接**：DOM 直取；需要"注册/点开"的，批量做（`Promise.all`），不要逐条 sleep。
