# 性能优化记录

| 场景 | 优化前 | 优化后 | 做法 |
|---|---|---|---|
| 知网检索 | 64.2s | 3.5s | 不等 `load`，只等结果表格稳定 |
| 纬度检索 | 61.7s | 11.8s | 同上 + 详情页批量注册/复核 |
| 馆藏 OPAC | 6.3s | 2.3s | 只等 `location.origin`，不等 SPA 启动 |
| 温度详情页 20 条 | 71.4s | 6.8s | 一次 eval 内 `Promise.all` 批量 |
| 默认 9 渠道 | — | ~9s | HTTP 渠道并行、浏览器渠道串行复用同一页面 |

## 四条纪律

1. **绝不等 `load` 事件**（发现系统/知网 load 可能 60s）→ 等 URL + 容器稳定。
2. **接口调用批量化**：逐条 eval → 一次批量，数量级提速。
3. **固定 `sleep` 换条件等待**（有上限），例如等首行标题变化、等卡片数稳定。
4. **一次拿全**：`--json` 落盘（SPIS 默认给详情页），绝不为取链接重跑检索。

## 限流与稳定性

- 强限流站要节流（例如畅想之星：连发会 429，需间隔 ≥2.5s；遇 429 停止，不重试）。
- 网络类错误（ETIMEDOUT/fetch failed）标记跳过，不阻塞整轮。
