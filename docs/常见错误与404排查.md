# 常见错误与 404 排查

> 目的：拿到"打不开 / 0 条 / 报错"时，能按现象查原因，而不是瞎试。
> 判据来自实测（校园网 + 受控浏览器），不是猜测。

## 0. 先分责：是谁的问题

| 现象 | 先查 | 结论 |
|---|---|---|
| 所有渠道都 0 条 | `node find.js --check` | 校园网没认证 / 断网 |
| 只有校内渠道 0 条，公开库正常 | 配置与认证 | 渠道未配置或 IP 不在校园网 |
| 单条链接打不开，其它正常 | 链接类型（见第 1 节） | 裸链未注册 / 反爬 / 签名过期 |
| 报错退出（exit 1） | stderr 最后一行 | 工具 bug 或网络错误，按第 3 节 |

## 1. 链接 / 404 类（重点）

| 现象 | 可能原因 | 怎么确认 | 处理 |
|---|---|---|---|
| SPIS 详情页新标签打开是 404 | **裸详情链未"注册"**；`gid` 拼出来的 URL 默认打不开 | 换成 `POST /api/article/saveDetail` 注册后再 `GET /api/article/data/<gid>` | 用工具默认详情模式（不写 `--link`）；手拼的 URL 一律不可信 |
| 页面 HTTP 200，但内容显示"404 / 未找到" | **SPA 软 404**：路由永远返回 200，JS 再显示错误 | 只看后端接口：`/api/article/data/<gid>` 返回对象才算有效 | 以接口为准；条目不丢，退回原文并标 ⚠️ |
| 出版社原文 403 / 429 | 反爬 / 限流，**不是 404** | `curl` 返回 403/429，浏览器能打开 | 如实标"反爬/限流"，不给假链接；改走详情页或文献求助 |
| 汇雅阅读链接过一会失效 | 链接带 `d/enc/t` **时效签名** | 当场搜到的链接当场打开 | 必须当场用；不保存、不转发 |
| `/book/detail?ssid=` 404 | 该路由不存在 | 打开 `/book/card?ssid=` 书目页 | 用 card 页 + reader，别用 detail 路由 |
| 读秀 `ruid/d/...` 链接失效 | 时效签名 | 重新检索取新链接 | 当场用 |
| DOI / 出版社原文 404 | 撤稿、换刊、迁移 | 查 Crossref/DOI 元数据 | 用 OA 版本（arXiv/PMC/DOAJ）或详情页 |
| 详情页数量少于条目数 | 部分条目注册不上 | 输出里的"无详情页 N 条" | 这些条目退回原文并标 ⚠️，不删条目 |

## 2. 结果 / 0 条类

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 命中 N 条，但列表为空 | 结果页"未找到"被当成结果页 | 直接用新版适配器（已检测无结果页并提前返回） |
| 中文关键词查 arXiv/GitHub/公开库几乎 0 条 | 这几家以英文为主 | 换英文关键词 |
| CNKI 加 `--type=硕士` 结果不符 | 类型是侧栏 facet，不是 URL 参数 | 用工具的类型过滤（已实现），不要手拼 URL |
| `--pages=2` 只回 1 页的量 | 翻页后等待条件不可靠 | 用新版（已改为比较同位置首行标题） |
| OPAC 命中 0 | 机构码未配置 / 多词是 AND | 查 `config.local.js` 的 `groupCode`；词少一点 |
| 某渠道返回 0 但站点明明有 | 未认证 → 跳登录页 | `--check`；登录校园网 |
| 畅想之星突然全失败 | 429 限流（`retry-after`） | 停止重试，隔一段时间再跑 |
| detail 模式很慢（~6s/条） | 掉进了"逐条点击"兜底 | 用新版：从卡片 DOM 构造 `saveDetail` 批量注册（8 条约 4–5s）；若仍慢，看是否大量条目没被 DOM 构造到（卡片缺失/选择器变了） |

## 3. 运行 / 环境类

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到可用的 Chromium 内核浏览器` | 未装 Chrome/Edge/Chromium/Brave | 安装其一，或设 `LITSEARCH_CHROME=路径` |
| 浏览器关不掉 | 进程被手动改过 / PID 文件丢了 | `node chrome.js stop`；仍不行按调试端口查（Windows `netstat -ano`） |
| `调试端口 9222 在 30000ms 内没起来` | Chrome 启动后退出：profile 不可写 / 端口被占 / 外层沙箱禁止 Chrome 自身 sandbox_init | ①新版默认 profile 在系统临时目录，先升级；②`node chrome.js stop` 清残留；③手动跑一次 Chrome 看真实报错（见下）；④若报 `sandbox initialization failed`，说明是外层 agent 沙箱限制 → 在宿主终端跑，或把该会话切到 danger-full-access |
| Windows 中文乱码 | 终端编码 | `chcp 65001` |
| `JSON.parse` 失败 | stdout 混入日志 | 确认用 `--json`；日志本来都在 stderr，不要自己重定向错 |
| headless 被站点 403 | 反自动化检测 | 已内置 UA 伪装；仍失败用 `--show-chrome` 观察后按反爬处理 |
| Node 报 `fetch`/`WebSocket` 不存在 | Node 版本太低 | 升级到 **Node ≥ 22** |

## 4. 报告格式（给用户或下一个 AI）

必须写清：**渠道 → 命中数 → 条目（标题/年份/被引/详情或原文）→ 每条链接的验证状态 → 失败原因分类**。

禁止：
- 编造 / 手打 / 省略链接（`…`、`<gid>`、`见上表`）；
- 把 403/429 说成 404；
- 把"没查到"说成"没有"；
- 没验证就标"已验证"。
